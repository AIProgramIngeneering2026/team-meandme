# ADR-0003. Общий демонстрационный каталог без аккаунтов

- Дата: 10 ноября 2026 года.
- Статус: принято.

## Контекст и ограничения

Первая версия анализирует тестовые изображения без персональных данных. Она не подключена к личным фотогалереям, не удаляет файлы и не выполняет оплачиваемых действий. Задача курса — проверить инженерные контракты при ограниченном объёме обработки.

## Решение

Сервис работает как один общий учебный экземпляр без аккаунтов. Каждый клиент может читать любой известный ID этого экземпляра. UUID затрудняет случайное угадывание, но не является механизмом доступа. Личные изображения и публикация такого экземпляра как многопользовательского продукта исключены.

Каталог задаётся конфигурацией. Для создания Job клиент передаёт только ID набора и операцию. Клиент, знающий ID задания, может отменить его до начала обработки. Это правило действует для общего учебного экземпляра. [ADR-0004](0004-cancel-created.md)

Границы ресурсов: тело создания до 8192 байт, набор из 1–10 элементов, каждый файл до 5 МиБ, каждый кадр до 12 000 000 пикселей, одно изображение без анимации, одна выполняемая работа и не более двадцати незавершённых Job. Скачивание ограничено временем на всю попытку, а не только ожиданием очередного байта. Лимиты и ответы перечислены в [описании API](../api/README.md).

## Альтернативы

| Вариант | Почему отклонён |
|---|---|
| Авторизация и персональные наборы | Требуют владельцев, разграничения доступа, хранения и удаления личных файлов |
| Приём произвольного URL | Добавляет непредсказуемые источники и отдельные требования к сетевому доступу |
| Нет лимитов, доверяем каталогу | Конфигурация или внешний источник могут измениться; ошибка должна завершать Job предсказуемо |

## Цена решения

Сервис нельзя использовать для личных фотографий нескольких пользователей. Для проверки PNG и отказов нужны локальные фикстуры и fake-источник, потому что обычная демонстрация использует JPEG Picsum.

## Условия пересмотра

Пересматриваем решение до добавления личных данных, аккаунтов или внешних клиентов. Тогда отдельно проектируем доступ к каждому Job, хранение оригиналов и удаление результатов.
