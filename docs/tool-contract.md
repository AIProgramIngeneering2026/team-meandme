# Контракт Tool

Tool — исполнитель одной операции над уже полученным набором изображений. Он не создаёт Job, не меняет его состояние и не знает HTTP-коды. Обе операции вызываются одинаково:

```text
Tool.execute(input: AnalysisInput) -> ToolSuccess | ToolFailure
Registry.get(operation) -> Tool | UnknownOperation
Dispatcher.execute(operation, input) -> ToolSuccess | ToolFailure
```

Это спецификация интерфейса, а не готовая реализация Python. Типы результата формализованы в [OpenAPI](api/openapi.yaml): `DuplicateData`, `QualityData`, `JobFailure`.

## Вход

`AnalysisInput` содержит `analysis_version = "1"` и упорядоченную коллекцию `images` из 1–10 элементов. У каждого элемента есть `image_id` (уникальная строка), `content` (неизменяемые исходные байты JPEG/PNG), `format`, `width`, `height`. Копия имеет собственный `image_id` и те же байты. Поля с URL, путями к файлам, SQL-сессией или HTTP-запросом отсутствуют. Порогами версии 1 управляет код контракта, а не пользователь.

| Условие | Кто проверяет | Отказ |
|---|---|---|
| JSON, поля запроса, ключ | HTTP API / JobService до создания Job | HTTP 400/413/415/422 по контракту API |
| Известная операция и набор | JobService; операция также проверяется Registry при вызове | `unknown_operation` / `unknown_dataset`; при создании Job не появляется |
| Состав, уникальность ID, допустимые ссылки копий и лимит 1–10 | Каталог до сохранения нового Job | 503 `catalog_unavailable`; ошибку конфигурации исправляет разработчик |
| Не более 5 МиБ, сетевой статус и тип ответа | ImageSource в процессе обработки | Доменная ошибка источника; Job становится `failed` |
| JPEG/PNG, один кадр, разрешение от 3×3, до 12 млн пикселей, декодируемость | Общая проверка файлов до Dispatcher | `invalid_image`, `unsupported_image_format`, `image_too_large` |
| Непустой вход, уникальные ID, версия анализа и согласованность метаданных | Каждый Tool при входе, включая прямой вызов в тесте | `invalid_tool_input` с указанием элемента/поля |

Tool доверяет проверке формата и лимитов вызывающей стороны, но проверяет собственные структурные предусловия. Если QualityAnalyzer всё же не смог декодировать переданные байты, возвращает `invalid_image`, а не падает наружу. Произвольные исключения считаются ошибкой реализации: Runner записывает безопасный `internal_error`, не раскрывая stack trace клиенту.

## Результат и ошибки

`ToolSuccess = {status: "ok", operation, data}`. `ToolFailure = {status: "error", error: {code, message, details}}`. Варианты взаимоисключающие: нет одновременных `data` и `error`, нет успешного частичного ответа. `details` — список `{field, reason}`; например, `field = "images.photo-10.content"`. Пустой список допустим, если ошибка не относится к конкретному полю. Сообщение понятно человеку, программная обработка опирается на `code`.

Tool не добавляет `job_id`, время или `correlation_id`. Runner связывает результат с Job и сохраняет его; HTTP-слой добавляет ID текущего HTTP-обращения к ответу. Повторные вызовы Tool с теми же байтами и версией дают одинаковые данные. Tool не изменяет вход, не ходит в сеть и БД, не пишет файлы, не удаляет оригиналы. Свои ошибки Tool не повторяет; сетевые повторы принадлежат адаптеру.

Ошибки двух Tool: `invalid_tool_input`, `invalid_image`, `unsupported_image_format`, `image_too_large`. `unknown_operation` возникает в Registry до вызова Tool. Сетевые коды `source_*` возникают до Tool и не маскируются как его ошибка. Список ошибок сохранённого Job, включая `execution_interrupted`, задан схемой `JobFailure` и [таблицей API](api/README.md#ошибки-обработки).

## DuplicateFinder

- Имя операции: `find_duplicates`.
- Для каждого элемента считается SHA-256 исходных байтов. Декодирование не меняет определение точной копии: другая кодировка или метаданные делают файл другим.
- Результат `DuplicateData` содержит `image_count` и `groups`. Группа содержит `sha256` в нижнем шестнадцатеричном регистре и `image_ids` минимум из двух ID.
- Внутри группы ID сортируются лексикографически; группы — по первому ID. Один ID входит максимум в одну группу. Одиночные файлы пропускаются. При отсутствии повторов `groups = []`, это успех.

Пример для A, точной копии B и другого C:

```json
{
  "status": "ok",
  "operation": "find_duplicates",
  "data": {
    "image_count": 3,
    "groups": [{
      "sha256": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
      "image_ids": ["A", "B"]
    }]
  }
}
```

Хеш в примере условный и иллюстрирует формат, а не результат расчёта реального изображения.

## QualityAnalyzer

- Имя операции: `assess_quality`.
- PNG с прозрачностью накладывается на белый фон; изображение переводится в RGB. Анализируются хранимые пиксели без масштабирования и автоматического изменения по EXIF.
- `Y = 0.299R + 0.587G + 0.114B`, диапазон 0–255. `brightness` — среднее Y. Значение меньше 40 даёт `low_brightness`.
- Для внутренних пикселей `L = Y_left + Y_right + Y_up + Y_down − 4Y`. `sharpness` — дисперсия L по генеральной совокупности (`ddof = 0`). Значение меньше 100 даёт `possible_blur`.
- Используется float64; сравнение с порогами выполняется до округления. Значение, равное порогу, не вызывает предупреждения. NaN и Infinity не выдаются.
- `QualityData` содержит `image_count`, `thresholds` и `images`. Каждый элемент набора представлен один раз; порядок результатов — по `image_id`. У предупреждений порядок фиксирован: сначала `low_brightness`, затем `possible_blur`; каждый код встречается максимум один раз.

Пример результата одного тёмного однородного изображения:

```json
{
  "status": "ok",
  "operation": "assess_quality",
  "data": {
    "image_count": 1,
    "thresholds": {"brightness": 40, "sharpness": 100},
    "images": [{
      "image_id": "dark-01",
      "brightness": 20,
      "sharpness": 0,
      "warnings": [
        {"code": "low_brightness", "reason": "Средняя яркость 20 ниже порога 40"},
        {"code": "possible_blur", "reason": "Дисперсия Лапласа 0 ниже порога 100"}
      ]
    }]
  }
}
```

Предупреждения — успешный результат. Runner сохраняет `done`, а не `failed`. Эвристика может отмечать намеренно тёмные или гладкие изображения; художественное качество она не оценивает.

## Подключение нового исполнителя

Новый класс реализует тот же `execute`, получает уникальное имя и регистрируется при сборке приложения. Для его публичного использования обновляются схема `Operation`, вход/выход API, документация и тесты; управляющий алгоритм Dispatcher не меняется. Неизвестное имя никогда не превращается в произвольный импорт или выполнение кода.
